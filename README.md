## 🌳 权利要求树

> **权利要求树是连接技术方案与专利保护的桥梁**

### 什么是权利要求树？

权利要求树是一种**层次化的技术特征组织结构**，它将复杂的技术方案拆解为可独立保护的技术模块。本技能采用的权利要求树基本结构如下：

```json
{
    "一种……方法/系统": {
        "description": "{独权1描述}",
        "contains": {
            "{步骤1名称}": {
                "description": "{步骤1描述}",
                "contains": {
                    "{子步骤1名称}": {
                        "description": "{子步骤1描述}",
                        "special claims": [
                            "{子步骤1特殊设计点1}"
                        ],
                        "contains": {
                            "{子步骤1-1名称}": {
                                "description": "{子步骤1-1描述}",
                            },
                            "{子步骤1-2名称}": {
                                "description": "{子步骤1-2描述}",
                            }
                        }
                    },
                    "{子步骤2名称}": {
                        "description": "{子步骤2描述}",
                        "contains": {
                            "{子步骤2-1名称}": {
                                "description": "{子步骤2-1描述}",
                            },
                            "{子步骤2-2名称}": {
                                "description": "{子步骤2-2描述}",
                            }
                        }
                    }
                },
                "special claims": [
                    "{步骤1特殊设计点1}"
                ]
            },
            "{步骤2名称}": {
                "description": "{步骤2描述}",
                "special claims": [
                    "{步骤2特殊设计点1}"
                ]
            }
        }
    },
    // 若有更多独权，结构类似
    "一种……方法/系统":{
      ......
    }
}
```
**核心字段说明：**
- `description`：该步骤的**详细描述**
- `contains`：**子步骤列表**
- `special claims`：**特殊设计点**（不构成步骤）

**对应权利要求书的撰写逻辑：**

```
  1. 一种……方法/系统，其特征在于，包括，
  步骤S1，{步骤1描述}；
  步骤S2，{步骤2描述}。
  2. 一种……方法/系统，其特征在于，包括，
  ......
  3. 根据权利要求1所述的一种……方法/系统，其特征在于，步骤S1中，{步骤1特殊设计点1}。
  4. 根据权利要求1所述的一种……方法/系统，其特征在于，步骤S1中，{子步骤1名称}，包括，
  步骤S111，{子步骤1-1描述}；
  步骤S112，{子步骤1-2描述}。
  5. 根据权利要求1所述的一种……方法/系统，其特征在于，步骤S1中，{子步骤2名称}，包括，
  步骤S121，{子步骤2-1描述}；
  步骤S122，{子步骤2-2描述}。
  6. 根据权利要求4所述的{子步骤1名称}，其特征在于，步骤S111中，{子步骤1特殊设计点1}；
  7. 根据权利要求1所述的一种……方法/系统，其特征在于，步骤S2中，{步骤2特殊设计点1}。
  ......
```

### 权利要求树在各阶段的演进

| 阶段 | 权利要求树状态 | 核心动作 |
|:-----|:-------------|:---------|
| **Stage 1** | `claim-tree-v1.json`（初始版本） | 从项目文件中直接提取原始技术特征 |
| **Stage 2** | 结合查新报告标注（特征级对比） | 标记哪些特征已被现有技术公开 |
| **Stage 3** | `portfolio-v2.json`（优化后） | 划分权利要求树的一级模块（方法/系统）到不同的专利中，每个专利对应一棵优化后的权利要求树 |
| **Stage 4** | `portfolio-v2.json`（优化后） | 基于优化后的专利组合和权利要求树，生成流程图和最终交底书 |

### 核心特性

#### 1️⃣ AI 驱动的检索词生成

**输入**：Stage 1 生成的 `claim-tree-v1.json`（权利要求树）

**处理流程**：
- AI 分析核心技术特征、关键技术术语和创新点
- 提取**中文检索词组合**（最多5组，每组1-3个关键词）
- 提取**英文检索词组合**（最多5组，语义对应但不必一一翻译）
- 每组提供 **2-3个备选方案**（若检索结果不足，依次尝试备选方案进行检索）

**输出示例**：
```json
// keyword-cn.json
[
    [["隐藏外键", "数据验证", "识别"],
      ["外键推断"], ["知识图谱", "数据库"]],  // 备选方案
    [["查询结果溯源", "抽象语法树"],
     ["查询结果溯源"]]        // 备选方案
]
```

#### 2️⃣ 多源检索

**中国知网 (CNKI) 检索**：
- **检索范围**：基本为中文专利
- **检索方式**：输入检索式（关键词用 `*` 连接）→ 点击搜索 → 翻页获取结果
- **数据提取**：**权利要求文本** 和 **摘要**
- **检索深度**：默认检索前6页（约120条结果），自动去重

**FreePatentsOnline (FPO) 检索**：
- **检索范围**：基本为海外专利（US/EP/WO/JP/KR Patents/Apps）
- **检索方式**：输入检索式（关键词用 `AND` 连接）→ 勾选"其他专利" → 搜索
- **数据提取**：**Abstract** 和 **Claims**
- **检索深度**：默认检索前1页（约50条结果），自动去重

**WebSearch 补充检索**：
- **检索范围**：技术白皮书、行业报告、博客、学术预印本等
- **触发条件**：当 CNKI/FPO 检索结果不足时自动启动
- **目的**：补充非专利文献，发现潜在现有技术

#### 3️⃣ 整理与项目相关的现有技术

> **从海量检索结果中筛选高价值对比文件，建立技术特征映射**

**核心工作：建立技术特征映射表**

| 本申请技术特征 | 对比文件 D1 (CN123456A) | 对比文件 D2 (US2023/1234) | 对比文件 D3 (白皮书) |
|:-------------|:----------------------|:------------------------|:-------------------|
| 特征 A：预测模型 | ✅ 完全公开 | ⚠️ 部分公开（仅提及） | ❌ 未公开 |
| 特征 B：动态负载均衡 | ⚠️ 部分公开（静态权重） | ✅ 完全公开 | ✅ 完全公开 |
| 特征 C：多策略调度 | ❌ 未公开 | ❌ 未公开 | ⚠️ 部分公开（2种策略）|
| 特征 D：自适应阈值调整 | ❌ 未公开 | ❌ 未公开 | ❌ 未公开 |

## 三、专利法"三性"评估

### 3.1 新颖性评估（专利法第22条第2款）
> 新颖性：该发明不属于现有技术，也没有任何单位或个人就同样的发明在申请日以前向国务院专利行政部门提出过申请。

- **评估结论**：[具备/不具备] 新颖性
- **评估依据**：
  - 本专利的核心技术方案是否已被单篇对比文件完全公开
  - 是否存在抵触申请（申请在先、公开在后的专利申请）
  - 区别技术特征是否使本专利与现有技术产生实质性差异

### 3.2 创造性评估（专利法第22条第3款）
> 创造性：与现有技术相比，该发明具有突出的实质性特点和显著的进步。

**（1）突出的实质性特点判断**
- **评估结论**：[具备/不具备] 突出的实质性特点
- **判断方法**：采用"三步法"进行分析
  - **第一步：确定最接近的现有技术**
    - 最接近的对比文件：[专利或技术名]
    - 选择理由：[技术领域相同/技术问题相似/技术效果接近]

  - **第二步：确定区别特征和实际解决的技术问题**
    - 区别特征：[列出所有区别技术特征]
    - 实际解决的技术问题：[基于区别特征所能达到的技术效果确定]

  - **第三步：判断是否显而易见**
    - 对比文件是否给出技术启示：[是/否]
    - 本领域技术人员是否容易想到：[是/否]
    - 是否存在结合障碍：[如有，说明]

**（2）显著进步判断**
- **评估结论**：[具备/不具备] 显著进步
- **判断依据**：

  - 是否提供了不同技术思路：[说明]
  - 是否代表技术发展趋势：[说明]

**（3）创造性辅助判断因素**

## ⚔️ 六轮对抗与组合优化 {#六轮对抗}

> **通过系统性攻防演练，打磨出高质量专利组合**

### 核心流程

```
Step 1: 读取查新报告 → Step 2: 生成初始专利组合
                                  ↓
                        Step 3: 六轮博弈对抗
                        ┌─────────────────────┐
                        │ R1: 新颖性检验       │ ← 过滤无价值方案
                        │ R2: 规避路径攻击     │ ← 测试字面侵权边界
                        │ R3: 规避路径复查     │ ← 检查上位概括风险
                        │ R4: 等效侵权测试     │ ← 封堵替代方案
                        │ R5: 等效边界复查     │ ← 查漏补缺
                        │ R6: 整体质量审计     │ ← 确保撰写规范
                        └─────────────────────┘
                                  ↓
                Step 4: 输出优化结果 + 优化过程可视化报告
                                  ↓
                          Step 5: 用户确认
```

### 六轮对抗速览

| 轮次 | 攻击角色 | 攻击重点 | 防守策略 | 核心产出 |
|:-----|:---------|:---------|:---------|:---------|
| **R1** | 审查员 | 现有技术是否完全覆盖独权？ | 提取区别特征或主动放弃 | 过滤无新颖性方案 |
| **R2** | 竞争对手法务 | 替换/省略某个特征能否规避？ | 上位概括 + 从权补充具体实施 | 封堵字面规避路径 |
| **R3** | 竞争对手法务 | 上位概括是否过宽被现有技术覆盖？ | 收窄独权 + 从权保留宽范围 | 平衡防规避与防无效 |
| **R4** | 专利律师 | 等效替换（手段/功能/效果/显而易见性）是否成立？ | 不满足等效则补充从权保护 | 封堵等效侵权漏洞 |
| **R5** | 专利律师 | 数值边界、从权层次是否有遗漏？ | 补充封闭式权利要求 | 消除等效边界盲区 |
| **R6** | 资深代理师 | 从权布局/术语一致性/单一性/专利间协调 | 移除非必要特征、统一术语、修复引用关系 | 确保撰写规范合规 |

**布局策略说明**：

| 策略类型 | 适用场景 | 保护重点 |
|:---------|:---------|:---------|
| **主攻型** | 核心技术、竞争激烈领域 | 宽保护范围，优先国际布局 |
| **防守型** | 外围实施方式 | 封堵绕开路径，配合核心专利 |
| **隐藏型** | 难以逆向的核心算法/配方 | 作为商业秘密保护，不公开 |

**文件输出**：
- `portfolio-initial.json`：初始专利组合方案
- `portfolio-v2.json`：六轮对抗优化后的最终方案
- `R1.json` ~ `R6.json`：每轮攻防详细记录
- `claim-optimization.html`：可视化 HTML 页面
