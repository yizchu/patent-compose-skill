## 概述

本技能负责对**已成稿的专利申请文件**做授权前预演：先由智能体扮演**审查员**，依据专利法及实施细则逐轮出具模拟审查意见；再由智能体扮演**专利代理师**，逐轮完成意见陈述和权利要求修改。通过六轮交替对抗，在正式提交申请文件或答复真实审查意见之前，提前暴露驳回风险、验证答复思路、明确修改边界。

与 Stage 4（专利组合生成与权利要求树优化）的区别：Stage 4 是申请前从竞争对手视角优化保护范围，本技能是申请文件成稿后从审查员视角检验授权前景，视角、法律依据和产出均不相同。

### 预演轮次

| 轮次 | 审查角色 | 主要法律依据 | 代理师应对重点 |
|:-----|:---------|:-------------|:---------------|
| R1 | 客体与形式审查 | 专利法第2条第2款、第5条、第25条、第26条第4款（清楚）、第31条第1款；实施细则第二十三条第二款、第二十四条、第二十五条 | 修正不清楚的表述，删除或拆分不符合单一性的权利要求 |
| R2 | 新颖性审查 | 专利法第22条第2款 | 提取区别技术特征，限缩独立权利要求 |
| R3 | 创造性审查 | 专利法第22条第3款（三步法） | 论证非显而易见性，补充技术效果与对比数据依据 |
| R4 | 公开充分与支持审查 | 专利法第26条第3款、第26条第4款 | 从说明书原有记载中补入依据，调整权利要求的概括层次 |
| R5 | 修改超范围审查 | 专利法第33条 | 逐处核对修改的原始记载依据，回退无依据的修改 |
| R6 | 授权前景与答复策略审计 | 综合上述条款 | 输出授权概率、答复优先级、分案与主动修改预案 |

**触发方式**：按 R1→R6 交替执行 `office_action_rehearsal.md`（审查员视角）与 `office_action_response.md`（代理师视角）。

## 核心原则

- **条款对应**：每一条审查意见必须写明所依据的法律条款，不得给出“不符合规范”“撰写不当”这类无条款支撑的结论；每一条答复也必须针对具体条款逐一回应。
- **证据可溯源**：审查意见只能基于申请文件本身（权利要求书、说明书、摘要、附图）和 `${输出目录}/materials/prior-art-report.md` 的查新结果。需要补充对比文件时必须真实检索并标注来源，不得编造对比文件、公开号或公开日。
- **修改不超范围**：答复阶段的每一处修改都必须能在原始申请文件中找到明确记载（专利法第33条），并注明依据所在位置；找不到依据时只能陈述意见争辩，不得修改。
- **逐轮递进**：第 n 轮的审查意见必须建立在前 n-1 轮答复后的文本之上，不得重复提出已经答复并已解决的缺陷；每轮只在确有新问题时才继续提出意见。
- **真实性原则**：所有分析必须严格基于项目真实文件和真实检索结果，不得凭空捏造或臆测不存在的技术方案。
- **术语标准**：必须采用所属技术领域的通用技术术语，优先使用国家标准、行业标准规定的规范名词，以及国际专利分类表（IPC）中的标准技术术语。国家有统一规定的自然科学名词，应当采用官方统一术语；无官方规定的，可采用本领域约定俗成的表述，不得自行编造非通用词汇。禁止使用口头俗称、网络热词、行业黑话、非技术类表述替代专业术语。
- **通俗易懂**：用清晰直白的语言描述技术方案，确保非本领域技术人员也能理解，避免空泛赞美、营销口号、万能句式、结构模板、正确废话等具有“AI味”套话。
- **会话上下文管理**：每个 Step 结束后，都需要提醒用户注意会话上下文是否接近上限，若接近上限，建议用户在新会话继续后续步骤并告知智能体已经完成了哪些 Step。

## 工作流程

### Step 1：读取申请文件与查新报告

**`Read`** 以下文件：

- `${输出目录}/patents/{专利标题}/claims_{专利标题}.md` - 权利要求书（预演审查对象）
- `${输出目录}/patents/{专利标题}/specification_{专利标题}.md` - 说明书（判断公开充分和支持的依据）
- `${输出目录}/patents/{专利标题}/abstract_{专利标题}.md` - 摘要（检查与权利要求、说明书是否一致）
- `${输出目录}/patents/{专利标题}/flowcharts_{专利标题}.md` - 附图（核对附图标记与说明书是否对应）
- `${输出目录}/materials/prior-art-report.md` - 查新报告（判断新颖性、创造性的基础）

**明确了解**：每件专利的独立权利要求与从属权利要求层级、说明书公开的技术细节范围、查新报告已识别的区别技术特征和风险点。上述文件不全时，先提示用户补齐或缺哪一份，不得凭猜测预演。

### Step 2：六轮审查答复预演

逐轮交替执行两个提示词：

- 审查员视角（出具模拟审查意见）：**`Read`** `${SKILL_DIR}/skills/office-action-rehearsal/prompts/office_action_rehearsal.md`
- 代理师视角（意见陈述与修改）：**`Read`** `${SKILL_DIR}/skills/office-action-rehearsal/prompts/office_action_response.md`

每一轮结束后，立即将该轮完整记录保存为 `${输出目录}/office-action-rehearsal/R{n}.json`，采用 **YAML → JSON 两阶段生成法**（先 `Read` `${SKILL_DIR}/prompts/references/generate_json.md`，先生成 `.yaml` 再转换），并执行 `python "${SKILL_DIR}/scripts/file_tools.py" from_json <JSON文件路径>` 校验，校验通过并 **`Read`** 确认内容无误后才能进入下一轮。

### Step 3：生成预演报告

输出 `${输出目录}/materials/office-action-rehearsal-report.md`，报告结构与字段要求见两个提示词中的“输出要求”章节。

### Step 4：生成预演修改稿

输出 `${输出目录}/materials/amendment-draft.md`，给出预演修改后的权利要求书全文（标注修改痕迹）和逐处修改对照表（修改前、修改后、原始记载依据、修改理由、对保护范围的影响）。

### Step 5：用户确认

提醒用户逐条核对模拟审查意见是否成立、答复思路是否可用、每处修改是否超范围，同时提示用户“若会话上下文接近上限，可以在新会话继续之后的步骤，但要记得告诉智能体已经完成了Step X”。确认无误后本子技能才算完成；用户有异议时，结合反馈重做对应轮次，直到用户满意为止。

```

├── materials/
│   ├── office-action-rehearsal-report.md   # 审查答复预演报告（末尾附结构化 JSON）
│   └── amendment-draft.md                  # 预演修改稿与修改对照表
└── office-action-rehearsal/                # 六轮预演记录
    └── R1.json ~ R6.json                   # 每轮审查意见与答复详情
```

## 与其他阶段的关联

- **依赖 Stage 5**：需要交底书和附图判断说明书公开是否充分
- **依赖 Stage 6**：权利要求书是预演的主要审查对象
- **依赖 Stage 7**：说明书、摘要、附图与权利要求书的一致性检查
- **复用 Stage 3**：查新报告是新颖性、创造性预演的事实基础
- **可选执行**：不是必经流程，但在正式提交申请文件前、或收到真实审查意见通知书后自检答复思路时强烈建议执行

## 法律条款版本说明

本技能的条款编号以 2023 年 12 月 11 日修订、2024 年 1 月 20 日施行的《专利法实施细则》为准。引用时如需对照旧版，在括号内标注对应关系，例如：独立权利要求应当记载必要技术特征——现行细则第二十三条第二款（2010 年细则第二十条第二款）；单一性中“总的发明构思”——现行细则第三十九条（2010 年细则第三十四条）；针对通知书指出的缺陷进行修改——现行细则第五十七条第三款。
