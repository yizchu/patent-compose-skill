# Stage 6: 撰写专利申请文件

## 任务目标

基于 Stage 4 生成的最终交底书和附图、以及 Stage 5 生成的权利要求书，为每件专利撰写完整的**说明书**，并完成摘要撰写、附图标记注册和一致性检查，形成符合法定要求的专利申请文件四件套。

---

## 工作流程


### Step 1：必备材料检查

在开始撰写说明书之前，必须确认所有材料齐全。从 `${输出目录}/patents` 目录中获取所有文件夹，每个文件夹对应一个专利。**`Read`** 并验证以下文件是否存在且内容完整：

对于**每一件专利**（专利标题 = 文件夹名），必须具备：

1、**交底书**：`${输出目录}/patents/{专利标题}/disclosure_{专利标题}.md`
- 验证内容完整性：是否包含全部九个章节
- 验证技术方案详尽度：技术细节是否足以支撑说明书撰写

2、**权利要求书**：`${输出目录}/patents/{专利标题}/claims_{专利标题}.md`
- 验证技术特征完整性：编号连续，必要特征齐全，表述清楚无歧义，无模糊词语
- 验证术语统一性：全文术语一致，为说明书撰写做好准备
- 验证保护范围合理性：独立权利要求不过窄，从属权利要求层次清晰

3、**附图材料**：`${输出目录}/patents/{专利标题}/flowcharts_{专利标题}.md`
- 验证是否包含必要的 Mermaid 图表
- 确认图表类型是否与交底书中的技术方案匹配
- 确认所有图表没有语法错误，都能正常渲染显示

#### 缺失处理机制

如果发现任一材料缺失或内容不完整，**立即终止当前流程，引导用户补齐材料**：
```
检测到以下材料缺失或不完整：
- [具体缺失的材料名称]

请先完成 [对应的Stage] 以生成所需材料，然后再继续Stage 6。
```

只有当所有必备材料均通过验证后，才能进入 Step 2。

### Step 2：撰写说明书

说明书需按**法定五部分**撰写，每部分都有明确的材料来源和写作规范。

**`Read`** 以下输入文件以获取撰写素材：
- `${输出目录}/patents/{专利标题}/disclosure_{专利标题}.md`（交底书）
- `${输出目录}/patents/{专利标题}/claims_{专利标题}.md`（权利要求书）
- `${输出目录}/patents/{专利标题}/flowcharts_{专利标题}.md`（附图）

对**每一件专利**分别生成独立的说明书：

**输出位置**：`${输出目录}/patents/{专利标题}/specification_{专利标题}.md`

#### 各部分的主要材料来源
- 技术领域：专利名称 + 交底书第二章 "技术领域"
- 背景技术：交底书第三章 "背景技术"
- 发明内容：权利要求书直接转换
- 附图说明：交底书第九章 "附图说明"
- 具体实施方式：交底书第五章 "技术方案" 和第七章 "具体实施方式"

#### 各部分的写作规范

##### 技术领域
一句话表述，简洁明了

##### 背景技术
1. **复杂度控制**：尽量只选择 1 件现有技术写清楚，若 1 件实在无法代表所有技术方向，再写第 2 件。最多写 2 件。
2. **指出不足**：这些做法在实际应用中遇到的具体问题或局限性
3. **客观叙述**：按照交底书客观介绍和叙述现有技术的内容和不足，不添加任何主观解释或假设。
4. **自然过渡**：引出本发明要解决的技术问题（不出现"为了解决上述问题"等模板句式）
5. **格式规范（极其重要）**：
   - **禁止检索式表述**：不得出现"经检索发现"、"通过检索可知"、"检索结果显示"等字样
   - **禁止引用文献标识**：不得出现专利号（如CN123456789A）、论文URL、DOI编号、作者姓名等
   - **禁止使用小标题**：不得使用"方案一："、"方案二："、"对比文件1："等列表式小标题
   - **禁止列表式罗列**：不得用编号列表或符号列表形式罗列多个现有技术

##### 发明内容

权利要求书直接转换的规则：
1. **独立权利要求的转换**：
- `一种XXX方法，其特征在于，包括：` 转化为 `一种XXX方法，包括：`
- `一种XXX方法，其特征在于，具体有：` 转化为 `一种XXX方法，具体有：`
- **操作**：去除"其特征在于，"这几个字

2. **从属权利要求的转换**：
- `根据权利要求1所述的XXX方法，其特征在于，所述...，包括：` 转换为 `优选的，所述...，包括：`
- `根据权利要求1所述的XXX方法，其特征在于，所述...，具体有：` 转换为 `优选的，所述...，具体有：`
- **操作**：去除"根据权利要求N所述的....，其特征在于，"这些内容，替换成"优选的"


有益效果的撰写规则：
1. 单独成段，逐条列举
2. 每个效果都能对应到具体的技术手段（"通过什么技术，能达到什么效果"）
3. 禁止空洞定性（如"显著提高"、"大幅改善"而无具体说明）
4. 禁止商业宣传用语（如"业界领先"、"国际先进水平"）

##### 附图说明
- 图名简明扼要，能准确反映附图内容
- 每张图一句话说明，不超过两行
- 不在此处解释图中细节（细节在具体实施方式中说明）

##### 具体实施方式
撰写核心要求：
1. **公开充分**：描述深度必须达到所属技术领域技术人员无需创造性劳动即可重复实现的程度，所有权利要求的技术特征必须在本部分有对应的详细实现说明，不得隐瞒关键技术细节。
2. **客观严谨**：采用专利正式书面语，禁止口语化、宣传化、绝对化表述（不得使用 “最佳”“首创”“完美” 等词汇），仅客观描述技术结构、步骤、参数与技术效果。
3. **支撑权利要求**：实施例需覆盖权利要求的全部技术特征，核心创新点对应详细的实现过程，为权利要求的保护范围提供事实依据。
4. **结合附图**：涉及结构、流程的描述需对应附图标注（如 “如图 1 所示”），将附图编号与技术特征一一对应。

### Step 3：全面一致性检查

这是说明书撰写阶段的最后一道质量关卡，必须确保申请文件的各个组成部分协调一致。

#### 3.1 术语一致性检查

**检查维度**：
- 说明书与权利要求书中的**技术术语**完全一致
  - 例如：权利要求书用"预处理单元"，说明书不能用"预处理模块"
- 全文中**同一概念**使用同一表述
  - 例如：不能混用"图像"、"图片"、"影像"指代同一事物
- **上位概念与下位概念**的使用恰当
  - 权利要求书可用上位概念（如"处理装置"），说明书在下位展开时说明具体实现（如"CPU、GPU、FPGA等"）

**检查方法**：
1. 提取权利要求书中的所有关键词汇
2. 在说明书中逐一搜索这些词汇及其同义词
3. 标记不一致之处并修正

#### 3.2 技术特征顺序一致性

**检查维度**：
- 「发明内容」中的技术方案段落与**独立权利要求的步骤顺序**完全一致
- 「具体实施方式」的实施例1与**独立权利要求**的步骤展开一致
- 各实施例与**从属权利要求**的对应关系符合 `aligns_embodiment` 映射

**常见错误**：
- 发明内容先说步骤B再说步骤A，但权利要求书是A→B
- 实施例中展开了从属权利要求X的特征，但声称对齐的是从属权利要求Y

#### 3.3 附图标记一致性

**检查维度**（承接 Step 5）：
- 说明书中出现的每个附图标记都在附图中有对应元素
- 权利要求书中使用的附图标记与说明书完全一致
- 「附图说明」章节中提到的图号与实际附图数量匹配

#### 3.4 内容完整性检查

**检查清单**：

**结构完整性**：
- [ ] 是否包含全部五个法定部分（技术领域、背景技术、发明内容、附图说明、具体实施方式）
- [ ] 各部分标题是否准确无误
- [ ] 摘要是否已单独生成（abstract文件）

**技术内容完整性**：
- [ ] 背景技术是否叙述了至少1件现有技术的实际做法（非列表式）
- [ ] 发明内容的三个段落（问题、方案、效果）是否齐全
- [ ] 技术方案是否与独立权利要求同序
- [ ] 有益效果是否有技术机理支撑
- [ ] 具体实施方式是否足够详细（可重现）
- [ ] 实施例数量是否覆盖了主要的从属权利要求组合
- [ ] 公式/表格是否保留（未收成纯文字）

**撰写规范性**：
- [ ] 无"AI味"套话（空泛赞美、万能句式、营销口号）
- [ ] 语言通俗易懂（非本领域技术人员也能理解大致意思）
- [ ] 无商业宣传用语
- [ ] 无凭空捏造的技术内容（所有特征均有据可查）

#### 3.5 修正与迭代

如果在一致性检查中发现任何问题：

1. **定位问题**：明确记录问题的具体位置（文件名、行号、段落）
2. **执行修正**：直接编辑对应的 `.md` 文件
3. **循环验证**：修正后重新执行 6.1~6.4 的检查项，确保没有引入新问题

### Step 4：撰写说明书摘要

摘要是专利申请的法定公开文件，用于简明扼要地披露发明的核心技术内容，供公众快速检索与初步了解技术方案。基于说明书与权利要求书的核心内容撰写，单独成稿，保存到 `${输出目录}/patents/{专利标题}/abstract_{专利标题}.md`

#### 参考步骤
1. **核心信息提取**：从独立权利要求中提炼技术方案的核心框架（方法类提取核心步骤链路、系统类提取核心模块组成）；从发明目的中提取对应解决的关键技术问题；从有益效果中提取最具代表性的 1-2 项技术效果。
2. **逻辑串联成文**：按照 “技术领域→技术问题→核心技术方案→主要有益效果” 的逻辑顺序，将提取的信息组织为连贯的单段文字。
3. **合规校验与精简**：核对术语一致性，压缩冗余表述，调整字数至法定范围内，确保无违规表述。

#### 撰写规范
1. **要素完整性**：必须完整覆盖技术领域、所解决的技术问题、技术方案核心要点、主要有益效果四个法定要素。
2. **篇幅控制**：全文为单段文字，无标题、无多余格式标记。字数严格控制在 300 字以内，语言高度凝练，不展开实施细节。
3. **表述规范**：
   - 客观陈述技术内容，不使用 “本发明”“其特征在于” 等权利要求式表述，不出现评价性、宣传性用语
   - 不得包含附图标记、数学公式、表格、权利要求编号引用
   - 不得使用小标题、编号列表、项目符号等格式
   - 全文术语与说明书、权利要求书保持完全一致
4. **重点突出**：着重体现发明区别于现有技术的核心创新手段，无需展开从属权利要求的附加技术特征。

### Step 5：用户确认

提醒用户检查生成的说明书和摘要是否符合预期，重点确认：

1. **技术准确性**：技术方案描述是否与实际实现一致
2. **结构完整性**：五个法定部分是否齐全
3. **一致性**：与权利要求书是否协调一致
4. **可读性**：语言是否通顺易懂

如果用户有异议，需要结合用户反馈和已有材料进行修正，直到用户满意为止。

## 关键要求

### 法定合规性
- **五部分结构**：必须严格按"技术领域、背景技术、发明内容、附图说明、具体实施方式"五部分撰写，不可增减
- **同序原则**：发明内容的技术方案必须与独立权利要求的步骤顺序完全一致
- **支持性要求**：具体实施方式必须充分支撑权利要求书中的所有技术特征（尤其是从属权利要求）

### 真实性与准确性
- **最高原则**：所有内容必须基于交底书、权利要求书等真实材料
- **有据可查**：说明书中的每一个技术特征都必须能在交底书或权利要求书中找到依据
- **严禁捏造**：不得臆测、编造或添加原始材料中不存在的技术特征
- **交叉验证**：重要技术细节需与交底书、权利要求书交叉印证

### 术语规范
- **标准术语**：必须采用所属技术领域的通用技术术语，优先使用国家标准、行业标准规定的规范名词
- **统一性**：全文同一概念使用相同术语，与权利要求书保持一致
- **禁止用语**：禁止使用口头俗称、网络热词、行业黑话替代专业术语

### 通俗易懂
- **清晰直白**：用清晰直白的语言描述技术方案，确保非本领域技术人员也能理解基本原理
- **避免套话**：避免空泛赞美、营销口号、万能句式、结构模板、正确废话等具有"AI味"的套话
- **适度抽象**：对于复杂技术，可采用类比或分层描述的方式降低理解难度
