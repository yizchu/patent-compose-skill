# Stage 1: 分析项目，初步生成“权利要求树”

## 任务目标
遍历项目的所有文件，判断文件类型，根据图片和文字（如果是软件项目，还需要关注代码）分析项目架构，提取技术细节，最终生成一棵完整的“权利要求树”。

## 工作流程

### Step 1：收集文档信息
执行：
```bash
python "${SKILL_DIR}/scripts/analyze_project.py" get_files_info <项目根目录> <项目根目录>
```
输出目录下会生成 `project files` 目录，该目录**完全镜像项目的部分目录结构**，记录了项目中所有文档文件的内容，并额外包含一个 `files_info.json` 文件。文档文件范围仅限于 `${SKILL_DIR}/scripts/analyze_project.py` 中 `READ_EXTENSIONS` 常量定义的后缀文件。
- `files_info.json`：以树形结构记录整个项目的文档信息，根节点对应项目根目录，叶节点包含文档的基本信息（文件名、扩展名、前几行内容等），子节点为父节点对应目录下的子目录或文档。
- **其余文件夹**：与项目目录结构一一对应。例如，若项目中某JSON文档位于 `{项目根目录}/backend/config/xxx.json`，则输出目录下也会有 `project files/backend/config/` 路径。
- **最底层的文件夹**：以原项目文档命名（如 `xxx.json` 对应 `xxx.json/` 文件夹），其中包含从该文档中提取出的所有文本和图片：
  - 文本内容统一保存在 `content.md` 中
  - 图片直接保存在该文件夹内，依次按自增序号命名`image1.png`、`image2.png`……。

### Step 2：项目文档分析
1. **判断文件类型**
**`Read`** `${输出目录}/project files/files_info.json`，判断其中的文件：
- 哪些是已有交底书/专利申报建议/创新点汇总
- 哪些是项目文档（架构说明、设计文档、流程图等）
- 哪些是配置文件
- 哪些可以忽略
2. **精读文档文件**
遍历 `${输出目录}/project files` 目录下的所有文件夹，按优先级选取重要文件进行精读，提炼项目的技术细节（如：模块组成、函数调用关系、数据流向、机械结构、独特设计……）、识别潜在的专利点（如：独特算法、创新结构……），同时标注每个专利点的来源文件（使用其在项目目录下的相对路径）
3. **保存分析结果**
将分析结果保存到 `${输出目录}/materials/disclosure-v1.md` 文件中。如果没有分析出任何结果，也要创建一个空文件。

### Step 3：项目图片分析（如果有图片文件的话）
1. **精读图片文件**
遍历 `${输出目录}` 目录下的所有文件夹（包括`patent-compose output`目录），**`Read`** 所有的图片文件、提取图片内容，尝试从这些图片中提炼项目的技术细节（如：模块组成、函数调用关系、数据流向、机械结构、独特设计……）、识别潜在的专利点（如：独特算法、创新结构……），同时标注每个专利点的来源文件（使用其在项目目录下的相对路径）。
2. **保存分析结果**
**`Read`** `${输出目录}/materials/disclosure-v1.md`，将本次图片分析结果与之整合，覆盖 `${输出目录}/materials/disclosure-v1.md` 文件。

### Step 4：项目代码分析（如果有代码文件的话）
1. **安全检测**
执行以下命令进行代码敏感信息扫描：
```bash
python "${SKILL_DIR}/scripts/analyze_project.py" examine_code_file <项目根目录>
```
等待命令执行完成，仔细阅读输出的检测报告。无论是否检测到敏感信息，都必须告知用户，然后**暂停后续步骤**，等待用户回复确认再继续。

2. **对核心代码文件进行深度分析**
遍历 `${输出目录}` 目录下的所有文件夹（`patent-compose output`目录除外），分析所有的代码文件。代码文件范围仅限于 `${SKILL_DIR}/scripts/analyze_project.py` 中 `CODE_EXTENSIONS` 常量定义的后缀文件，**严禁读取**该常量之外的任何文件类型。

分析时需依项目领域灵活识别以下关注点（包括但不限于）：
- 核心算法与策略实现
- 业务逻辑与流程编排
- 数据处理与转换
- 规则引擎与决策逻辑
- 接口与集成设计
- 状态机与调度机制
- 性能优化与缓存策略
- 安全与权限控制

3. **保存分析结果**
**`Read`** `${输出目录}/materials/disclosure-v1.md`，将本次代码分析结果与之整合，覆盖 `${输出目录}/materials/disclosure-v1.md` 文件。

**提示**：
当代码文件数量庞大时，采用分批策略：
- **先读目录结构**：先了解项目整体架构，识别核心模块/服务目录/主要文件
- **优先处理核心**：先分析与项目核心功能最相关的文档和代码（如主入口文件、核心业务逻辑）
- **逐批深入**：按模块分批精读，每完成一个模块就将分析结果追加到 `disclosure-v1.md`，避免一次性加载过多内容
- **聚焦专利点**：对于明显属于第三方库、依赖包、自动生成代码、常规工具类的内容，可以快速跳过，集中精力分析项目独有的技术实现


### Step 5：初步生成“权利要求树”
**`Read`** `${输出目录}/materials/disclosure-v1.md` 文件，该文件已包含项目的分析结果。基于分析结果，构建一棵完整的“权利要求树”，用JSON格式表示，保存至 `${输出目录}/materials/claim-tree-v1.json` 文件。

**核心原则**：
- **尽可能多地提取专利点**：哪怕是不确定是否具备新颖性的技术点，也要先纳入树中。
- **层级清晰**：独立权利要求应包含某一技术方向的完整解决方案，从属权利要求逐层细化具体实现。例如，独权描述方法整体流程，从权A细化独权步骤1的具体实现，从权B细化独权步骤2的具体实现。低层级的权利要求写入 `contains` 字段（字典类型）。`contains` 字段的值**至少要有两个**键值对，若只有一个更低层级的权利要求，则不构成步骤划分，应将其融入 `description` 或 `special claims` 字段同时不要添加 `contains` 字段。
- **详细描述**：每个从权必须有几句话的详细描述，说明特征、作用、具体实现方式等，写入 `description` 字段（字符串类型）。`description` 字段**不可为空**。
- **特殊设计**：每个从权若包含特殊设计，如“知识图谱的实体id有一定规律从而间接携带信息”或“溯源以后，需要先尝试UTF-8解码，如果失败则尝试GBK解码，最后使用base64，保证数据能正常展示”等，则写入 `special claims` 字段（列表类型）。若没有特殊设计，则不要添加 `special claims` 字段。
- **顺序逻辑**：同一层级的节点，必须按逻辑先后顺序排列，不要照搬分析结果的写作顺序。
- **技术特征完整**：`contains`和`description`和`special claims`三个字段应共同展现技术特征的所有技术细节。
- **保护范围合理**：不要包含过多非必要技术特征，避免保护范围过窄。例如，独权写核心算法流程，而非具体参数配置。

### Step 6：用户确认
提醒用户检查分析结果和"权利要求树"是否符合预期，重点确认以下方面：
1. **专利点覆盖**：是否遗漏了重要技术方案
2. **独权保护范围**：独立权利要求是否包含过多非必要技术特征，导致保护范围过窄
3. **层级合理性**：权利要求树的层级划分是否清晰，从属权利要求是否恰当细化
4. **技术特征准确性**：描述是否准确反映项目实际实现

用户确认无误后，Stage1方可视为完成。若用户提出异议，需结合反馈意见与已有分析结果进行迭代修正，直至用户满意。完成后，主动提示用户："Stage1已完成，如果会话上下文接近上限，建议在新会话中继续后面的步骤，并请告知智能体已完成Stage1"。

## 关键要求
- **真实性原则**：所有分析必须严格基于项目的真实文件，不得凭空捏造或臆测不存在的技术方案
- **全面覆盖**：不能遗漏任何技术细节，只有明显属于行业常规实现的内容才可以省略
- **术语标准**：必须采用所属技术领域的通用技术术语，优先使用国家标准、行业标准规定的规范名词，以及国际专利分类表（IPC）中的标准技术术语。国家有统一规定的自然科学名词，应当采用官方统一术语；无官方规定的，可采用本领域约定俗成的表述，不得自行编造非通用词汇。禁止使用口头俗称、网络热词、行业黑话、非技术类表述替代专业术语。
- **通俗易懂**：用清晰直白的语言描述技术方案，确保非本领域技术人员也能理解，避免空泛赞美、营销口号、万能句式、结构模板、正确废话等具有“AI味”套话。
